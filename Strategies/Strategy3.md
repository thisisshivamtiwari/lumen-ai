# Strategy3: Build a verified graph-informed ranker

This plan supersedes unsupported assumptions in Strategy1/Strategy2 while retaining their useful integrity checks and domain reasoning. Its default is **one compact boosted tree model with transaction, directed behaviour and bounded graph features**. A second model, ensemble or graph score stage is conditional on honest AP gains. No universal best model or measured XRPL gain has been established. Research, sources, corrections and access limitations are in the [full report](../reports/XRPL%20strategy%20research.md). This is an implementation plan; no solution code, training or actual submission has been performed.

## 2. Make one transaction spine and two evidence views

Keep an immutable full ID table for every scored transaction. All feature tables left-join to it, asserting unchanged cardinality and unique feature keys. Preserve repeated sender/receiver payments as separate edges. Reconcile a small selection of plain transfers, conversions, self-conversions and missing-data rows with raw inputs and helper output.

Build the **economic graph** with one sender-to-ultimate-receiver edge per payment. Retain an **execution-leg table** for liquidity providers, assets and conversion characteristics. Never add sequential leg amounts into economic volume or count an atomic conversion as multiple independent laundering hops. Use documented leg ordering or path continuity; mark ambiguous reconstruction rather than using arbitrary row order/largest leg. Failed/no-transfer transactions still need predictions, but unsupported instructions must not create completed-flow edges.

Keep XRP integer drops, token decimal values, paid/delivered amounts, USD values and normalised amounts. Asset key follows the release's token-address/symbol specification. Validate hourly rate-key uniqueness and join to the containing UTC hour; preserve missing/invalid rate and JSON states separately from zero. Audit partial-payment delivered value where relevant. Unknown real-ledger transaction types are conditional work, not a reason to expand scope before profiling. ([XRPL Payment](https://xrpl.org/docs/references/protocol/transactions/types/payment); [partial payments](https://xrpl.org/docs/concepts/payment-types/partial-payments))

## 3. Establish an honest baseline and fixed validation matrix

Run the supplied baseline and a small CatBoost/LightGBM configuration selected by environment availability. Start with raw payment fields, safe transforms and parse/rate masks. Preserve identifiers for joins; exclude arbitrary ID ordering from the robust default and perform an explicit artefact audit. Keep continuous output precision; do not optimise a 0.5 threshold, round scores or apply default isotonic calibration. Verify that library `PR-AUC` matches the exact AP definition before using it for selection. ([Official AP](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html))

Select the primary holdout from release mechanics. Use genuine scenario groups if available and suitable; inspect component sizes and positive-bearing group counts before considering component CV. A giant component joined through a legitimate exchange is not an independent scenario. Add a small wallet/pair-disjoint stress check and chronological/boundary diagnostic where feasible. Seven days makes temporal estimates noisy, not useless. In batch mode reproduce permitted full-window unlabelled context; in causal mode exclude future edges. Labels remain training-only in both modes.

Save paired predictions, exact AP, per-fold positive counts, pooled OOF AP and mean-fold AP separately. Reserve an untouched confirmation holdout if group/positive counts support it. Inspect hubs, conversions, tiny/large amounts, unseen endpoints/assets, sparse history, boundaries and missing-data slices. Compare candidates on identical slice rows; prevalence differences prevent direct interpretation of AP across slices. All-positive pattern/difficulty slices need a fixed negative background and global top-k recall diagnostics.

## 4. Add cheap behaviour before bounded motifs

First test separate source/destination incoming/outgoing counts, unique counterparties, log volume, amount median/IQR, asset-conditioned variability, reciprocity, pair recurrence, interarrival median/IQR and first/last observed exposure. Include raw amounts alongside local relative amounts and ratios. Port/normalised port rank and seen-before indicators are optional small ablations. Test a few short/medium/long windows rather than a huge feature grid.

Then add bounded two-to-four-hop **static participation** and **time-respecting participation** as separate blocks. Use edge roles: fan-out origin, forwarding intermediary, fan-in sink and cycle closure. Chronological paths require distinct economic transactions and documented ordering, not atomic LP legs. Equal timestamps without ledger order remain ambiguous. Log degree/search caps so truncation cannot masquerade as low activity. ([Multi-GNN utilities](https://github.com/IBM/Multi-GNN/blob/main/data_util.py); [GFP paper](https://arxiv.org/html/2402.08593v2))

Use lag, same-asset amount error and conversion-aware USD compatibility as graded features. Test split/merge totals and partial forwarding; do not require exact equality or infer FIFO provenance. Distinguish XRP burn, token fees, spread and rate uncertainty rather than imposing one fixed drops tolerance. Observed cumulative net flow is not account balance; first observed is not proven new. Add left/right censoring and exposure indicators and crop context as a stress test.

Inspect legitimate payroll fan-out, merchant fan-in, treasury movement, refunds, recurrent bots, self-conversions and exchange hubs. Also inspect suspicious payments inside otherwise legitimate neighbourhoods, disconnected fraud, overlapping motifs and incomplete paths. Neither rarity, dust, high amount nor conversion alone determines suspicion. Tags, if supplied, are address-scoped statistics; equal tags across addresses do not establish identity. Use small known-answer fixtures for parser/graph correctness, not a custom synthetic training generator without a performance oracle.

## 5. Gate optional complexity on full-pipeline evidence

Retain a feature block only when paired primary-holdout AP improves, runtime remains reproducible, and no material unexplained hub/worst-fold regression appears. Investigate one-scenario gains; do not invent a universal minimum AP delta. Adversarial validation diagnoses shift: inspect and ablate suspicious features, rather than automatically removing everything that distinguishes train/test. Keep raw and behaviour-normalised branches where useful.

Train a complementary model only after the feature baseline is stable. Compare best single model, probability mean and normalised rank mean on identical honest predictions. Retain an ensemble only when it beats its strongest member with useful error complementarity and no major stress collapse. Seeds/model-family names do not prove diversity; rank averaging can create ties and change ordering.

**No-go by default:** component-max smoothing, in-sample neighbour scores, global OOF graph stacking, broad GNN migration and dependency-heavy generator installation. If stage two is attempted, protect each outer holdout from every first-stage fit; inner-cross-fit inside outer training to generate stage-two training inputs; generate validation neighbour scores only from outer-training models; exclude self/duplicate contributions and assess the complete stage on untouched outer labels. A neighbour's OOF model can otherwise have seen the central edge's label. Check full-training inference score alignment too. Omit stage two if this cannot be audited. ([Stacking guidance](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.StackingClassifier.html))

Snap ML GFP is optional only after terms, compatible installation and a tiny correctness smoke test. Current package metadata uses IBM ILAN terms and lists macOS x86_64 wheels rather than native arm64. Prefer narrow documented graph statistics in the existing environment. ([Package metadata](https://pypi.org/project/snapml/))
